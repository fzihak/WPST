## Symptoms

- Google Search Console flags URLs under **Core Web Vitals**: `"LCP issue: longer than 2.5s (mobile)"`, `"INP issue: longer than 200ms (mobile)"`, or `"CLS issue: more than 0.1 (mobile)"`.
- Pages score poorly on Google PageSpeed Insights (PSI) or Lighthouse, with warnings: *"Eliminate render-blocking resources"*, *"Avoid an excessive DOM size"*, or *"Reduce initial server response time"*.
- Mobile users experience noticeable lag when tapping navigation menus, accordion tabs, or add-to-cart buttons (high INP).
- Page content visibly jumps or shifts downwards while images, web fonts, or banner ads load (high CLS).
- The hero image or banner at the top of the viewport takes several seconds to render despite fast network speeds (slow LCP).

## Possible Causes

1. **Slow LCP (Largest Contentful Paint > 2.5s)**:
   - High Time to First Byte (TTFB) delaying the initial HTML delivery.
   - Render-blocking CSS and JavaScript in the document `<head>` postponing browser paint.
   - Hero images lazy-loaded (`loading="lazy"`) or lacking modern format compression (AVIF/WebP).
   - Missing resource hints (`fetchpriority="high"`, `rel="preload"`) for the above-the-fold image.
2. **High INP (Interaction to Next Paint > 200ms)**:
   - Monolithic JavaScript bundles (Elementor, jQuery sliders, mega-menus, tracking pixels) running heavy main-thread tasks (`Long Tasks > 50ms`).
   - Bloated DOM tree (`> 1,500 total nodes` or depth `> 32`) forcing excessive style recalculations and layout passes on user interaction.
3. **High CLS (Cumulative Layout Shift > 0.1)**:
   - Images, banners, or video iframes rendered without explicit `width` and `height` aspect ratio attributes in HTML.
   - Web fonts loading with invisible text flash (FOIT) without `font-display: swap` or layout-matched fallback fonts.
   - Dynamic injected elements (cookie banners, marketing notification bars, ads) inserted above existing content after page load.

## Prerequisites

- Access to WordPress Administrator dashboard with theme and caching plugin settings access.
- Google Chrome browser to use DevTools (Performance, Network, and Lighthouse panels).
- Access to PageSpeed Insights or WebPageTest to measure real-world field and synthetic lab metrics.
- Access to child theme or custom code snippet manager to apply resource hints and attributes.

## Investigation

1. **Audit with Chrome DevTools Performance Panel**:
   - Open Chrome DevTools → **Performance** tab.
   - Enable **CPU: 4x slowdown** and **Network: Fast 4G** (simulates real mobile devices).
   - Record a page load, scroll, and click on an interactive element.
   - Check the **Timings** track for **LCP**, **DCL**, and **Long Tasks** (red flags on main thread).

2. **Identify the exact LCP element**:
   In Lighthouse or DevTools Performance, find the **Largest Contentful Paint** entry. Note the HTML element (e.g., `<img>`, `<h1>`, or background image container).

3. **Check whether the LCP hero image is wrongly lazy-loaded**:
   Inspect the hero image HTML tag:

```html
<!-- BAD: Delaying LCP by waiting for scroll listener -->
<img src="hero.jpg" loading="lazy" class="hero-image" />

<!-- GOOD: Immediate priority loading -->
<img src="hero.jpg" fetchpriority="high" loading="eager" width="1200" height="600" />
```

4. **Identify CLS offenders via DevTools Layout Shifts**:
   - In DevTools → **Performance**, check the **Experience** track.
   - Click on each **Layout Shift** block to see which DOM element moved and the shift score contribution.

5. **Profile Main-Thread JavaScript blocking (INP)**:
   - Look for script evaluation tasks exceeding 50ms.
   - Common culprits: Tag managers, hotjar, live chat widgets, mega-menus, complex sliders.

::: investigate
Investigation mindset: Core Web Vitals are **user-centric perceptual metrics**, not just arbitrary page weight. You don't have to delete your plugins to pass; you must control **when** code executes. Critical CSS and hero images must load first; everything else (analytics, chat, below-the-fold scripts) must yield the main thread.
:::

## Diagnosis

| Failing Metric | Observed Diagnostic Symptom | Remediation Target |
| --- | --- | --- |
| LCP > 2.5s | Hero image has `loading="lazy"` attribute | Remove lazy-loading on first image; add `fetchpriority="high"` |
| LCP > 2.5s | Render-blocking CSS/JS files in `<head>` | Defer non-critical JS; inline Critical CSS or preconnect fonts |
| INP > 200ms | Clicking button triggers >250ms Long Task | Defer third-party tracking scripts; reduce DOM tree depth |
| CLS > 0.1 | Content jumps when image or ad finishes loading | Add explicit `width` and `height` attributes or CSS `aspect-ratio` |
| CLS > 0.1 | Text font shifts when custom web font loads | Add `font-display: swap` and match font metric overrides |

## Resolution

1. **Optimize Largest Contentful Paint (LCP)**:
   - Disable lazy-loading on the very first image of any template:

```php
// In functions.php or mu-plugin: Exclude hero image from lazy loading
add_filter( 'wp_content_img_tag', function( $filtered_image, $context, $attachment_id ) {
    static $image_counter = 0;
    $image_counter++;

    // First image in content should NOT be lazy-loaded and must have high fetchpriority
    if ( 1 === $image_counter ) {
        $filtered_image = str_replace( 'loading="lazy"', 'loading="eager" fetchpriority="high"', $filtered_image );
    }
    return $filtered_image;
}, 10, 3 );
```

   - Preload the LCP hero image in `<head>`:

```html
<link rel="preload" as="image" href="/wp-content/uploads/2026/02/hero-banner.webp" fetchpriority="high">
```

2. **Fix Cumulative Layout Shift (CLS)**:
   - Ensure every image and video tag defines aspect ratio dimensions:

```html
<!-- Explicit dimensions prevent reflow -->
<img src="logo.png" width="240" height="60" alt="Brand Logo" style="height: auto;" />
```

   - Prevent font shift flash by enforcing `font-display: swap`:

```css
/* In theme stylesheet */
@font-face {
    font-family: 'Inter';
    src: url('/fonts/inter.woff2') format('woff2');
    font-display: swap;
}
```

   - Reserve layout space for ads, cookie banners, and dynamic containers using CSS:

```css
.ad-slot-container {
    min-height: 250px; /* Reserve space before ad script loads */
}
```

3. **Reduce Interaction to Next Paint (INP)**:
   - Defer non-essential third-party analytics and marketing scripts (Google Tag Manager, Meta Pixel, Hotjar):

```html
<script src="https://www.googletagmanager.com/gtag/js?id=G-XXXXX" defer></script>
```

   - Defer or delay non-critical JavaScript using a modern performance plugin (Perfmatters, FlyingPress, or LiteSpeed Cache Delay JS).
   - Break up heavy JavaScript event handlers using `requestIdleCallback` or `setTimeout`:

```javascript
// Yield main thread to allow browser paint
function handleUserInteraction() {
    // Quick UI feedback immediately
    button.classList.add('loading');
    
    // Defer heavy calculation
    setTimeout(() => {
        executeHeavyOperation();
    }, 0);
}
```

4. **Reduce DOM Size**:
   - Flatten page builder container nesting (e.g. Elementor Flexbox Containers instead of legacy Sections > Columns > Inner Sections).
   - Paginate long comment sections and large product listings.

## Verification

- Re-test the URL in **Google PageSpeed Insights**:
  Confirm metrics transition to the green zone:
  - **LCP**: `< 2.5s`
  - **INP**: `< 200ms`
  - **CLS**: `< 0.1`
- Re-run Chrome DevTools Performance profile:
  Verify the **Long Tasks** total duration drops significantly and the LCP timing marker fires early in the waterfall.
- Verify visual stability: Scroll and interact on mobile viewport; confirm zero visible content reflows.

## Root Cause

Core Web Vitals measure the real-world user experience across three critical dimensions: loading speed (LCP), responsiveness (INP), and visual stability (CLS). In WordPress, regressions are primarily driven by unconstrained plugin bloat: third-party scripts monopolizing the main browser thread, un-sized responsive media forcing layout reflows, and excessive render-blocking assets in the document `<head>`.

## Prevention

- Enforce a strict performance budget during development: maximum 1MB page weight, maximum 50 HTTP requests.
- Always declare `width` and `height` on custom templates, logos, and widget images.
- Host web fonts locally in `.woff2` format with `font-display: swap`.
- Audit new plugins in Chrome DevTools for main-thread CPU time before approving them on production.
